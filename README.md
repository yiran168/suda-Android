素打是一款本地优先的便携式热敏打印创作工具，面向连续纸与标签纸，把文字、图片、二维码、一维条码、形状、OCR、行业模板和变量数据统一放进可编辑画布。从毫米级纸张设置、203 dpi 同源预览到蓝牙发送打印，编辑与输出共用同一套坐标和点阵流程；连续纸按内容自动算长，标签纸按设定宽高输出。核心编辑、识别、模板、历史和设置均保存在设备本地，应用不申请网络权限。

本工程不是 HAP 转 APK，也没有复用上游 HarmonyOS UI；Android 端使用 Kotlin、Jetpack Compose 和 Material 3 独立实现，最低 Android 7.0（API 24），以 Android 16（API 36）为编译和行为目标。

## 已实现

- Qring / BeePrt BY 经典蓝牙 SPP：扫描、已配对设备、自动重连、安全/非安全 RFCOMM 回退。
- Qring 私有状态协议：空闲时读取电量、打印中、开盖、缺纸、低电压和温度；多份打印期间暂停状态轮询，只以当前打印事务的明确故障帧为准，避免标签间隙误报缺纸或过热。
- Qring 多份可靠节奏：每份独立发送并等待当前 ACK，再同时满足点阵高度截止时间与 ACK 后 6.5 秒固件复位截止时间；下一份不会因设备提前回 ACK 而被静默吞掉。
- 通用 ESC/POS 光栅模式（无 Qring 私有状态读数）。
- 同源点阵渲染：屏幕最终预览与打印使用同一张位图，避免密度单位造成偏移。
- 连续纸自动算长：内容最下边界 + 校准偏移 + 底部留白 = 光栅高度；无需长度传感器。
- 10.0–57.0 mm 无极纸宽：毫米 × DPI 精确换算，可按 0.1 mm 调节并输入小数；所有小于 55.0 mm 的纸都要求确认靠左/靠右装入，固定打印头光栅中的纸外列保持全白且不会加热。固定标签另可设置长度、横纵偏移和标签间隙。
- 低延迟可交互编辑器：稳定指针协程、浮点位移累计、合并渲染队列；点击选中、拖动、双指缩放，也可用单指拖动完整四边与四角独立改宽高；轻量磁吸只在 2 点内捕获，并允许慢速手势脱离；支持多选、持久组合/解组、吸附参考线、六向对齐、水平/垂直分布、旋转、锁定、复制、删除、图层移动和撤销/重做。
- 编辑器使用固定实时画布 + 独立滚动属性区；画布底边可连续拖动高度，也可收起后重新展开；长卷画布限制屏幕占用并可在画布内上下阅读，修改参数时预览不会被滚走。
- 纸张类型与尺寸只在新建任务时选择，进入画布后不重复展示；画布下方保留浓度和选中元素的就地属性。
- 新建任务时独立选择连续纸/标签纸、宽高、标签形状和间隙；新增横线、方格、清单、空白四类便签纸。
- 标签预设为 30×20、40×30、50×30、50×50、57×30 mm；连续纸预设按 57、50、40、30 mm 排列，所有选择块等宽。
- 元素：文字、图片、19 种一维/二维编码、可编辑表格、20 种形状、日期时间、递增流水号、手绘/签名。
- 文字：系统字体族及内置马善政、龙藏体、志莽行书、刘建毛草 4 套真实中文字体，8–120 点字号、100–900 无级字重（快捷项仅 400/700）、斜体、下划线、竖排、对齐、字间距和行间距；字体许可证随应用保留。
- 图片：适应/裁切/拉伸、亮度、对比度、反色、阈值，以及 8 种二值化/抖动算法。
- 二维码与一维码分开创建；19 种码制采用输入智能清洗、长度补齐、校验位重算和最终 QR 安全回退，避免空白/崩溃预览；内置 16 种二维码内容结构，支持相册及相机识码。
- 拍照打印会先进入独立取景页，可用手指沿内容边缘自由画出闭合套索，圈外像素自动转为白色；也可直接使用整张照片。相册图片、拍照/相册离线中文 OCR 的识别行按原图位置转换成独立可编辑文字层，模型随 APK 内置，不依赖网络下载。
- 文档直印支持 PDF、DOCX、PPTX、旧版 DOC/WPS、旧版 PPT/DPS、XLSX/XLS/ET 与 TXT/Markdown：先检查 ZIP/OLE 内部结构，再参考扩展名和 MIME，避免 WPS 将 Word/PPT 错报为 Excel。每一页都能切换查看和编辑，并可全选或勾选指定页打印。PDF 使用原页点阵，PPTX 保留幻灯片坐标层，DOCX 保留可解析的段落、分页、表格和图片；旧二进制 Office 由 Android POI 5.5.1 转成可编辑段落、表格、基础样式和受支持的位图。暂停时保存页/份数/光栅行断点，必须明确选择继续或结束任务。
- CSV、TSV、Excel `.xlsx` 与 WPS OOXML 变量数据导入：字段可通过 `{{列名}}` 绑定到文字、条码、表格和流水号，支持记录预览与整表批量打印。
- 从 `模板图片` 的 197 张本地截图识别并重建 360 个模板，分为通用、商业、餐饮、医药、办公、通讯、居家、生产、仓储、收款码、其他；70 个原宽超过 57 mm 的模板按比例缩到 55 mm。
- 模板不是整张截图打印：装饰层可替换/解锁，OCR 文字与检测出的二维码是独立元素，可移动、缩放、删除和改字；构建时执行分类、纸宽、铺满、越界、严重重叠和缩团检查，360 个模板须以零错误、零警告通过。
- 图片按 EXIF 方向读取原始宽高比，新插入/替换时自动贴合；图片和文字均支持等比缩放滑条、物理毫米数值输入，文字字号也可滑动或输入并同步调整选框，旧元素可一键按实际内容收紧边界。
- 本地模板、JSON 导入导出、打印历史、失败记录与一键重新编辑。
- 流水号批量打印时逐份递增。
- 10 套独立视觉系统，其中新增冰晶磨砂、流体、烟熏、棱镜 4 种玻璃主题；每套拥有不同背景光场、透明表面、字体、形状、边界和层级，不是简单换色。
- 自动重连上次设备，采用 1/2/4/8/15/30 秒退避；发送打印时可选 12 种内置音效、随机内置、本地随机生成或静音。
- 不申请网络权限；模板、历史和设置全部保存在本机。

## 构建

1. 安装 Android Studio（带 JDK 17）与 Android SDK 36。
2. 在 Android Studio 中打开本目录 `android-app`，等待 Gradle Sync。
3. 选择 `app` 配置，执行 **Build > Build APK(s)**。
4. 调试 APK 位于 `app/build/outputs/apk/debug/app-debug.apk`。

命令行（本机已安装 Gradle 时）：

```text
gradle :app:assembleDebug
gradle :app:testDebugUnitTest
```

本工程在 JDK 17、Gradle 8.13、Android SDK 36 下执行 JVM 单元测试、`lintRelease`、Release 构建，以及 V2/V3 发布签名校验。当前 Release 有意关闭 R8 与资源裁剪：模板、OCR、扫码等离线路径包含动态资源访问，可靠性优先于 APK 体积。最终交付前以当前构建输出为准。

发布版本需要在 Android Studio 的 **Generate Signed App Bundle or APK** 中创建你自己的签名。不要把 keystore、口令或 `local.properties` 提交到仓库。

## 首次使用与校准

1. 在系统蓝牙页面先配对打印机。
2. 打开设置页第一个“打印机与连接”选项并连接设备；Android 12 及以上允许“附近设备”权限，旧系统扫描时允许定位权限。
3. 在“设备校准”中输入实际纸宽（10.0–57.0 mm），窄纸选择实际靠左或靠右装入，再打印带毫米刻度和四边框的校准样张。
4. 若边框整体左右偏移，以 0.1 mm 调“横向微调”；若起印位置上下偏移，调“纵向偏移”。保存后画布、最终预览和发送位图共用这套点阵坐标。
5. 连续纸只需设置尾部走纸，长度由内容自动计算；标签纸设置真实标签长度与两张标签之间需要补偿的间隙。

### 为什么没有长度传感器也能自动打印连续纸

热敏打印并不需要先“检测纸有多长”。光栅命令头包含本次位图的行数；App 根据所有元素的打印点坐标求出最下边界，再加留白，打印机自然只走这些行。红外传感器只负责判断有没有纸。

### 标签纸的物理限制

只有缺纸红外、没有缝隙/黑标传感器的机器，软件无法知道每张标签的真实起点。单张可以按设定长度精确输出；多张连续打印会累积机械误差，因此 App 提供标签间隙与纵向偏移校准，但不能声称自动寻标。若要求大批量逐张对齐，需要带缝隙或黑标传感器的打印机。

## 代码结构

```text
app/src/main/java/com/qrint/studio/
├── data/       360 个分层模板、质量门禁、变量表解析与本地持久化
├── model/      文档、纸张、校准、字体、元素及 JSON 模型
├── printer/    SPP 连接状态机、Qring 协议、打印队列
├── render/     同源渲染、条码安全层、离线 OCR、8 种抖动、光栅编码
└── ui/         Material 3 页面、模板中心与手势编辑器
```

渲染与协议层不依赖页面状态。模板、历史和编辑器都复用同一个 `LabelDocument`，遵循 DRY；新增元素类型时只需补充模型、渲染器和属性面板。

模板重建工具位于 `tools/extract_hprt_templates.py` 与 `tools/generate_editable_template_catalog.py`；OCR 元数据保存在 `template-source/hprt_templates.json`，生成的装饰层在 `res/drawable-nodpi`。Android 运行时不包含 Python 或 OCR 依赖。

重新生成模板时，可先在独立 Python 环境安装 `tools/requirements-template-extraction.txt`，再依次运行两个脚本。第一个脚本接收截图目录和 JSON 输出路径；第二个脚本接收 JSON、截图目录、资源输出目录与 Kotlin 清单输出路径。生成文件提交后，最终 APK 仍完全离线且不需要 OCR 库。

## 兼容性说明

- `minSdk 24`：Android 7.0。PP-OCRv6 Small 官方检测模型使用 ONNX IR v10，因此不再支持 Android 5/6。
- `compileSdk/targetSdk 36`：Android 16 API 与行为目标。
- AndroidX 依赖锁定在经过 API 24–36 构建验证的稳定版本；不要仅为消除“有新版”提示而无审查升级依赖线。
- Android 12+ 使用 `BLUETOOTH_SCAN` / `BLUETOOTH_CONNECT`；Android 7–11 仅扫描时请求定位。
- 图库通过 Storage Access Framework 打开，不依赖旧式绝对文件路径。
- 长画布上限 8,000 行（203 dpi 时约 1 米）；渲染按行二值化并对图片采样，避免低内存设备因超长位图闪退。更长内容请拆成多个打印任务。
- 主页面与画布采用互斥生命周期，进入画布前释放模板缩略图；打印预览位图由 Compose 生命周期统一持有和回收，避免回收与绘制竞争。导入文档还会统一校验纸张、元素数量、尺寸、浮点值和重复 ID。
- 本地异常日志只保存最近一次堆栈、设备版本和发生阶段，不记录标签文字或图片；若仍发生未捕获异常，下次启动会显示“检测到上次异常”，可复制诊断信息。
- BLE 没有默认开启：上游作者与公开 Issue 均表明这批设备真正打印通道是 SPP；“能扫描和连接 BLE”不等于知道其写入特征与协议。
